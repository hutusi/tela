# AGENTS.md

Guidance for AI coding agents (Claude Code, Codex, Cursor, …) working in this repository. This file is the single source of truth — CLAUDE.md imports it.

## Project

Tela is a multilingual reader and gathering place for independent blogs: readers subscribe to feeds, bloggers claim theirs and see who reads them, and LLM translation shows a post beside its original block by block. Bun workspaces and TypeScript throughout; three Cloudflare Workers (tela-web at the edge, tela-api and tela-jobs pinned beside a D1 primary in Singapore), a fourth, tela-gateway, at the edge for approved apps, and a fifth, tela-redirect, for Tela's old address; R2 and Queues; a Vite + React reader that renders from the device, and one Node process (the China relay) that runs only if a feed ever needs it.

Decisions that look odd but are deliberate:

- **Sign-up is a switch the operator flips while Tela runs, not a deploy.** `signup.mode` (ADR 0056) is `invite` by default: an account needs an invitation (a member's code, five people each, ever; an operator's code with as many uses as it was given; or `bun run admin invite`), and one gate, better-auth's `user.create.before`, admits all three by claiming the invitation in one statement and refuses by throwing (ADR 0034). `open` admits any proved address, still claims an invitation first when there is one, and pauses new accounts at `signup.maxPerDay` until the next UTC day. Settings like this one live in the `settings` table, read inline by the statement that enforces them (`settingSql`), audited, and changed from the console or `bun run admin set`; a limit of `null` is none and `0` is nothing at all. The site is `noindex` while `TELA_NOINDEX` is set in `apps/reader/wrangler.jsonc` (ADR 0060), whatever the mode. Members sign in by email code, password, Google or GitHub, the sheet opens on the password, and joining by email chooses one (ADR 0043); a password is set only once a code has proved the address, and a provider is linked to a member only from Settings, never by a matching address (ADR 0036). A missing hook context is never permission, in either mode.
- **A deleted account is closed, never deleted.** `closeAccount` empties it in one batch and keeps the `user` and `profiles` rows as shells with the handle, so nothing cascades through other members' rows and nobody takes the handle to pass as them; `member.erase` removes what its own devices held in chunks 10 minutes later, and `closures/<id>` in R2 lets a restore close it again (ADR 0058). A suspended account (ADR 0059) is hidden by the same predicate, `standingOk`.
- **Ordinary accounts have limits; translations past one wait rather than fail.** New body translations are counted per member per UTC day, and past that count or the site's daily token budget a request waits for the next UTC midnight (`due_at`), one day deep (ADR 0057). Feeds new to Tela are counted per day, an import's overflow waits in `pending_feeds`, and subscriptions are capped (ADR 0063). Full posts from blogs a member doesn't subscribe to are counted per day too, on the web and in every app together, and public answers carry no content key to get round it (ADR 0066). Admins are exempt from member limits on the web, never through an app, and never from the site total.
- **Apps act only by bearer token, on a host of their own, and are never admin.** `api.telaread.com` is tela-gateway (ADR 0065), where Tela's host-only cookies never arrive; tela-api mounts the app surface at `/gateway/*`, outside `/api/`, and no internal route reads a token. Any member registers an app in Settings → Developer (ADR 0067); one Tela has not reviewed holds at most 100 members across its developer's unreviewed apps, never sees an email address, and is shown as "Not reviewed by Tela", and only the operator's apps may say "Tela". The member connects it at `telaread.com/connect` through Tela's own OAuth server (better-auth has none; ADR 0064), and every rule runs for it with `exempt: false`, even on the operator's account. `apps.status` keeps `draft`/`approved`/`suspended` (Testing, Live, Cut off): a new value or any table-level CHECK on `apps` rebuilds the table, and on D1 that DROP TABLE cascades into every connection. It reuses the web's rules, never its routes: each rule is a function in `apps/api/src/core/` (or `@tela/data`) that takes an actor, and each API route has a format of its own in `packages/ext`, so the web's routes stay free to change while v1 moves only by addition. Connections end wherever sessions end, in the same batch.
- **The reader never waits on the network.** Every screen renders from the rows the device holds in IndexedDB, and a seq-cursor sync keeps them current behind it; an RPC is only for an answer the member is waiting for (ADR 0025).
- **Reading languages are a fixed launch set**, never "every language a subscriber speaks": translation cost is bounded by the set, not by the audience (ADR 0006). The set is Simplified and Traditional Chinese, English and French, and each is also an interface language (ADR 0038).
- **The model never writes Traditional Chinese.** It writes Simplified, and OpenCC converts (Taiwan phrasing): between the two scripts nothing is paid, and from any other language one Simplified translation serves both (ADR 0038).
- **Titles translate eagerly, bodies lazily and streamed**, so a reader never pays for a post they do not open and sees the first paragraphs in seconds (ADRs 0006, 0023).
- **Portable by construction.** Only `packages/platform/src/cloudflare.ts` touches a binding; the suite runs everything on libSQL, memory blobs and an in-process queue, and the nightly export restores into any SQLite. Leaving Cloudflare is a weekend (ADR 0021).
- **Background work is state, not messages.** A domain row says what is due, a lease says who holds it, and a queue only speeds that up (ADR 0020).
- **`telaread.com` is the only origin for people, and `api.telaread.com` the only one for apps** (ADR 0065). `workers.dev` is off on purpose: it is blocked in mainland China, so that URL is a dead link for part of the audience. The old address, `tela.ainaive.com`, and `www.telaread.com` only redirect there, through `tela-redirect`, whose `/sw.js` is the kill switch that retires the old address's shell worker: it must never become a redirect (ADR 0042).

bun run admin curate                 # add the curated blogs, featuring those marked (apps/api/scripts/curated-sites.ts)
bun run admin grant <email>          # open the admin console (/admin) to a member; ungrant closes it (ADR 0039)
bun run admin settings               # the runtime settings; `bun run admin set <key> <value>` changes one (ADR 0056)
bun run admin closures               # after any restore or Time Travel rollback: close again the accounts closed since (ADR 0058)

## Development workflow

- **Branch only for big work** — a feature, a large refactor, a dependency upgrade — on a `<type>/<topic>` branch off `main`. Bug fixes, small improvements and doc edits commit straight to `main`. Judge by scope and risk, not file count.
- **Commit in focused slices**, keeping lint green at each so branches stay bisectable. Conventional Commits. **No `Co-Authored-By` trailers and no AI-attribution lines anywhere** — commits or PR descriptions.
- **Explain the why in the commit body.** The subject says what changed; the body says why, and names any non-obvious trade-off. `git log` should make sense without opening the PR.
- **Docs and tests ship *with* the change.** The Docs section below says what each page tracks; `test/docs.test.ts` catches the drift that can be caught mechanically, which is not most of it.
- **Verify gate**, the list CI runs: `bun run lint && bun run typecheck && bun run test && bun run test:workers && bun run e2e`. CI also bundles the five Workers and builds the relay image; run those when you touch build config, a `wrangler.jsonc`, the Dockerfile, or a dependency.
- **Pushing, opening PRs and deploying are user-authorized** — don't do any of them unless asked.

## Hard invariants — do not break casually

1. **Runtime-agnostic packages.** No `Bun.*` APIs in `packages/*` or app source: the Workers run on workerd and the relay on Node 24, with Bun only as the toolchain (ADR 0001).
2. **Only `packages/platform/src/cloudflare.ts` touches a Cloudflare binding.** Only the fetch handlers of the Singapore-pinned Workers query D1; cron and queue handlers dispatch to them over `SELF.fetch()` (ADR 0020).
3. **Batch-only SQL.** A `Db` has no `transaction()`, and the portable libSQL client throws if one is reached. Anything that must be atomic is a single statement or a `db.batch([...])`. D1 offers nothing else.
4. **Nothing exceeds D1's per-statement limits:** 100 bound parameters, 100 KB of SQL, five terms in a `UNION`/`INTERSECT`/`EXCEPT` chain (SQLite allows 500; a 40-row `union all` seed failed on D1 while libSQL took it). Bulk work passes one JSON parameter through `json_each(?1)`; a multi-row `VALUES` is not a compound and is fine. The portable client enforces all three, so the test that trips it is the one to fix, not the limit.
5. **Know what a write touched through `RETURNING`, never the run result.** D1 and libSQL report affected rows differently, so `Db`'s run result is `unknown` on purpose.
6. **Background work is state-driven and idempotent.** A domain row says what is due; `claimDue` takes it under a lease, and a queue only speeds that up. Any write decided in JavaScript commits as a fenced batch (`fence(...)` first, `release(...)` last), so a holder that lost its lease writes nothing. A re-run must not duplicate rows or re-translate cached blocks. Never add a job whose only record is a queue message.
7. **A batch that writes a synced row starts with `bumpSeq(db)` and stamps `seq: currentSeq`.** Otherwise readers never see the change.
8. **The UI reads only the local store.** The admin console is the one exception (ADR 0039): an operator-only chunk that reads tela-api and writes nothing to the device. A new view renders from `useTables()`; a change is a mutation (`packages/sync/src/mutations.ts`, applied on the server in `apps/api/src/sync/push.ts` and predicted in `packages/sync/src/client.ts`), guarded by its client id and resolved by the later `at`. A protocol change a cached shell cannot read bumps `MIN_CLIENT` (and deploys tela-web before tela-api, OPERATIONS.md). Every member call names the member (`x-tela-member`), and every write to the device's stored copy checks its owner inside the same IndexedDB transaction.
9. **Migrations via `bun run db:generate`**, reviewed and committed, applied with `wrangler d1 migrations apply`. Never edit one that has been applied to production.
10. **Bump `NORM_VERSION`** whenever what a tagged text means or how it is hashed changes in `packages/content`: the placeholder grammar, the tagged-text serialization, the hash input. It is part of every block hash, so a silent change mixes old and new cache entries (ADR 0005). A fix to which elements become leaves keeps it, provided every tree without the fixed shape annotates byte-identically: show that with the fixture snapshots and stored bodies, and say so in the commit (ADR 0053).
11. **Model output is never trusted as HTML.** Text segments are re-escaped on rehydration, and a translation is accepted only when its placeholder multiset matches the source. Validation stays in `translateBlocks` (ADR 0005).
12. **Outbound fetches refuse private ranges.** The HTTP client checks names and literals, Cloudflare's `global_fetch_strictly_public` refuses the socket, and the relay pins the address it resolved. The relay serves only signed `POST /fetch`, follows no redirects and caps the body: it is not an open proxy (ADR 0008).
13. **Reading languages are the launch set in `packages/shared/src/languages.ts`** (ADR 0006).
14. **Never name a package script `prepare`, `postinstall`, or another npm lifecycle hook** — Bun runs them on install.
15. **Bump `PIPELINE_VERSION`** (`packages/shared/src/constants.ts`) with any change to what `processArticleHtml` makes of a body: sanitizing, normalization, skip rules, excerpts, and every `NORM_VERSION` bump. `article.reprocess` then makes each article's current version again from its stored raw HTML, adding a version only where the content object changed (ADR 0055). Forgotten, the fix reaches only what is fetched after it. A change to *extraction* is not this: the raw HTML Tela stores is Readability's output, so a better extraction still needs the page fetched again (OPERATIONS.md).
16. **A page fetch asks the blog first.** Feeds are read as any feed reader reads them, but every fetch of a blog's *pages* (extraction, a favicon's home page, anything new) calls `checkRobots` and respects `sites.feed_only` ("Only use what my feed provides", ADR 0061).
17. **The API host is bearer-only, and nothing else takes a bearer token.** tela-gateway drops every cookie and refuses any credential but an access token; tela-api's `/gateway/*` reads no session, and no `/api/*` route reads a token (a test walks Hono's route table). Never enable better-auth's `bearer` plugin: its token is a full session, admin flag and all (ADR 0064). No web route is served on the API host: an app reaches a web rule only through a `/gateway` route of its own.
18. **An app is never admin or exempt.** Its principal (`AppPrincipal`) carries no admin flag, and every shared rule is called for it with `exempt: false`, the operator's own account included. An API route passes `false`, never anything read from `is_admin`.
19. **Shared rules take an actor and never read a request.** A rule the web and the API both apply is a function in `apps/api/src/core/` or `@tela/data` that takes `{userId, exempt}` and returns a plain result: no `c.get('member')`, no headers, no `is_admin` inside it. Each surface words the result its own way (ADR 0065).
20. **v1's output changes only by addition, or in a new version.** Every v1 answer comes from a mapper in `packages/ext`, checked `.strict()` against the golden fixtures under `docs/api/`. When a shared function's change moves one, fix the mapper, not the fixture; a change that cannot be additive is v2 (`docs/api/policy.md`).
21. **Public JSON never carries a content key.** Public answers select `PUBLIC_ARTICLE_COLUMNS`; a member opens a public post through `GET /api/v1/articles/:id` (an app, `/v1/articles/{id}`), and fetching its body is where the day's limit counts (ADR 0066). A test finds every GET under `/api/v1/public` in Hono's table.

## Style

- TypeScript strict, `verbatimModuleSyntax`, `noUncheckedIndexedAccess`. No enums: `as const` unions.
- Single quotes, no semicolons, trailing commas. Biome owns formatting and linting for everything; there is no second formatter.
- Tests are `*.test.ts` beside the code or under `test/`; Playwright specs are `*.e2e.ts`.
- **`@types/node` tracks the relay's runtime major** (Node 24, per `.node-version` and `engines`), not the newest release. Types ahead of the runtime typecheck APIs that are not there when it runs; `test/docs.test.ts` holds the two together.
- Use absolute paths in shell commands — the working directory persists between them.

## Gotchas

Defects that already cost time here, not hypotheticals.

- **A header breakpoint has a width budget, and `md` is where it runs out.** Turning the wordmark and a fixed 240px search field on together at 768px cost more than the viewport gained, so the nav — the one flex item with `min-w-0` — absorbed all of it and rendered 4px wide: no pointer route to Dashboard or Settings anywhere from 768px to about 1100px, and nobody noticed because the Playwright matrix ran 412 and 1280. Stage the controls across `lg` and `xl`, keep exactly one shrinkable item (the nav, which scrolls; everything else is `shrink-0` from `sm` up or it wraps its label into the 56px bar), and measure at the breakpoint itself — `styles.e2e.ts` does.
- **An unlayered rule in `styles.css` beats every Tailwind utility.** Tailwind v4 emits utilities into `@layer utilities`, and an unlayered declaration outranks every layered one whatever its specificity. An `a { }` block outside a layer made 30 `hover:no-underline` and every `text-ink` on a link dead code while the class strings still read correctly. Base element styles go in `@layer base`; `styles.e2e.ts` asserts the computed values, because nothing in the JSX shows this.
- **A card that clips its overflow cuts off its own menus.** The Subscriptions manager rounded its corners with `overflow: clip`, and the folder menu of its last row opened past the card's foot, unseen and unclickable (Playwright: "`<main>` intercepts pointer events"). `hidden` does the same and stops `sticky` inside it too. Round the pieces at the corners instead (ADR 0049).
- **Two Tailwind utilities for the same property under different variants have no defined winner.** `data-[read=1]:opacity-[.62]` against `data-[active=1]:opacity-100` resolves by Tailwind's emission order, not by the order in the class string. Where one must beat the other, write both in `styles.css` and let source order say so.
- **A literal colour in a class list is a bug on the dark ground.** `bg-white` was on 31 elements, each of which stayed white in dark mode until it became `bg-surface`. Name a token; `styles.e2e.ts` checks both themes.
- **`:lang()` matches every descendant, so a size set with it outranks each element's own.** `.article-body :lang(zh)` (0,2,0) meant "Chinese text" and reached every heading, `code`, caption and table in a Chinese body, since language is inherited: a post's section headings rendered at body size while the stored `<h2>`s were right. Set a script's size on the body itself (`.article-body:lang(zh)`) and keep sizes inside it relative. And Tailwind's preflight is still under the article: it takes list markers away and makes every image a block, so `.article-body` restores both. `styles.e2e.ts` measures every block in both scripts and three layouts (`e2e/formatting.ts`).
- **Two owners of one piece of state is the bug, not the symptom.** The URL alone says which article is open; anything else that claims to know (a cache, a closure) disagrees after Back restores an entry. The Postgres app settled that inline three reviews running (ADR 0017); the SPA has no second owner.
- **A handler reads the state it acts on when it runs, not when it was bound.** A second `j` can arrive before React has rendered the first one's navigation; the keyboard layer stepped from the wrong article until it read the URL at keypress time. Same for which article a close closed, and the answer travels with the navigation: the close puts the id in the list entry's state, never in a ref an intermediate render can consume. A ref was consumed by the render a `j` had already committed, so focus went to the article the `j` showed, not the one closed. Back to that entry (`useNavigationType()` is `POP`) ignores the state and focuses the article last shown.
- **A fresh array every render is a loop once a layout effect sets state from it.** The untranslated-blocks list was rebuilt per render, harmless until the highlight hook (which runs after each body render) depended on it: React error #185, and every reading spec failed. Memoize what an effect depends on, and set state only when it changed.
- **Create the abort signal once per request, not inside the redirect loop**, or every hop gets the full timeout again: 100 ms was observed taking ~500 ms through five redirects.
- **A job's work must fit its lease.** A body translation holds its lease four minutes at a time, extending it in the batch that commits each chunk, and starts no chunk after ten minutes of the consumer's fifteen; the next execution continues from the cache. One that outlived its lease would run beside its own retry and pay the provider twice. A title job once committed all of a feed's (language, source) groups in one batch at the end: a feed in two source languages makes four calls, and at 80 s a call the fence refused all four at 320 s of a 300 s lease. Each group now commits as it lands, and each call first extends the lease, so a holder whose lease went while a call failed pays for no other: checking only after a call that succeeded let it send the next group's regardless.
- **Two writers of different kinds can hold leases on the same article at once.** A feed's fetch, an extraction and a reprocess each lease their own key, and each picks the next version number from what it read: both took version 2, the second insert was ignored, and its unguarded update pointed the article at the first writer's row with the second's content key, for good (Codex's review). An article now moves only from the version it was read at, onto a row holding the content it brings, and a writer reads `RETURNING` to know whether it moved anything (`pointAt`, `updateArticles`; ADR 0055). A losing writer must also keep a way back: a feed's batch saves its ETag and body hash, so a rejected change would hide behind the next 304 for good, and `replayIfRejected` clears them in the same batch (Codex's second review). That cannot mend a reprocess that made the same body first, on the same row: the next fetch finds the body stored and skips the item, so an edited title stayed stale and a corrected link was never extracted. A change therefore also lands, in full, on an article already on the row it chose (Codex's third and fourth reviews); splitting off only the title and link left the extraction request behind. A new writer of versions takes the same guard, and says how it retries.
- **A feed's size is not what it costs to store.** `ingestFeed` held every processed item, its content object and raw HTML included, until the batch: about 13 times the feed, so danluu.com's 6.6 MB feed took 85 MB of a 128 MB isolate (V8), and a feed near the old 5 MB cap was already close. Each item's objects are now written as it is processed and let go (`objectWriter`), decided by the same test the plan uses (`unchanged`). Measure a change to what the pipeline keeps against a large real feed, with a full GC before each reading.
- **A lease attempt is counted when the work starts, not when it fails.** A Worker killed over its CPU or memory limit reports nothing, and its lease simply expires; counted at failure, that item was re-claimed every TTL for ever, and for a body translation every re-claim repeats a paid model call. `runJob` calls `startLease` before any work, and `tick` retires a re-claimed item that has spent its attempts instead of sending it.
- **Queues deliver at least once, so a claim starts once.** A start that only renewed the claim let two deliveries of one message both start under the claim's owner, both pass the fence, and send every block of a body translation to the model twice. `startLease` moves the lease to a random run owner (`<claim>><run>`) in the statement that counts the attempt; the second delivery then matches nothing and is `lost`. Everything after the start uses the lease it returns, never the message's owner.
- **GLM copies straight quotes into JSON unescaped**, invalidating the whole reply and making the job retry into the same reply; `packages/llm` recovers entries one at a time by id.
- **`LLM_PROVIDER` without a matching key falls back to the mock, and the translation kinds are then disabled** — placeholder output would be cached for everyone. Set `LLM_PROVIDER=mock` deliberately for e2e and local runs.
- **A title may legitimately translate to itself.** `validateTranslation` rejects an echo, so the title block opts out by id and the row is recorded as `echo`, not retried. Excerpts and bodies keep the check, and an echo is deliberately **not** written to the shared block cache: it is content-addressed and first-write-wins, so a body `<h1>` repeating the headline hashes identically and would inherit the judgement forever.

- **Never edit `zh-Hant.json` or `content/info/zh-Hant.ts` by hand, and never ask the model for `zh-Hant`.** They are generated from Simplified by OpenCC (`bun run i18n:hant`, with `messages/zh-Hant.overrides.json` for Taiwan usage), as are the admin console's and tela-api's mail (`apps/api/src/mail-text/zh-Hant.json`), and a test fails when they drift. So `detectLanguage` lets a hint decide only very short text or a near tie, and the feed pipeline hints with the blog's own majority before the feed's tag. Measure a detector change against real posts, not sentences written to pass.
- **On a post that is mostly pictures, Readability's biggest block of text is not the post.** On maggieappleton.com it took a Hebrew webmention (spared from its comment filter because an ancestor's class said `content`), a backlink card, and, with no text left at all, the site menu. (Inside a paragraph the sanitizer drops the template, so nothing leaked into prose.) `extractArticle` removes those first and refuses a link-dense result. Readability had also left the `<tr>` without its table, so the row was the only block. Look at the stored object, not the page: a translation that reads as one paragraph is a leaf with too much in it.
- **Readability's class heuristics read a Tailwind utility as a verdict.** Its negative pattern has `scroll`, `hidden`, `media`, `meta`, `share`…, and it deletes any `h1`/`h2` whose class matches: `scroll-mt-[72px]` on every heading took all of aihero.dev's section headings, words and all, and `overflow-*` wrappers cost web.dev whole sections. - **Drizzle's table config names columns by their schema keys.** Under `casing: 'snake_case'`, `getTableConfig` reports `userId` for the column `user_id`; the export queried a column that does not exist until it converted with `toSnakeCase` for keys marked `keyAsName`.
- **`OFFSET` paging under concurrent writes repeats and skips rows.** The nightly export read each table `order by key limit 1000 offset n` while translations landed: a row written behind the cursor (its key sorting before the last one read) moved every later row one place on, so the row at the page boundary was exported twice, and a deletion behind it skipped one instead. The export verified, since the manifest counted the same lines it wrote, and the restore stopped at `UNIQUE constraint failed`. - **SQLite's `INSERT … SELECT … ON CONFLICT` needs a `WHERE` on the SELECT**, or the upsert clause parses as a join constraint. `WHERE true` is enough; `claimDue` is the example.
- **A column named `end` (or another keyword) works only quoted in raw SQL.** `highlights.end` is `"end"` in every hand-written statement; the D1 run pushes a highlight to prove it.

Returning `false` makes `createUser` return null, and the code sign-in then fails on `newUser.id` with an empty 500, the six digits already spent: throw an `APIError`. The context is missing wherever better-auth was not entered through an endpoint (the admin route's `internalAdapter.createUser` today, a background task or a refactor tomorrow), so never read its absence as permission: the admin route writes the operator's invitation first, and the gate claims it like anyone's. And a `create.after` that throws leaves the user row behind, which better-auth never creates again: the profile is written again, idempotently, by `session.create.after`.
- **better-auth's `getCookieCache` picks the cookie's name from `NODE_ENV` unless told.** On an https origin the cookie is `__Secure-tela.session_data`. A check that leaves `isSecure` unset reads the other name, finds nothing, and falls back to a D1 read on every request, silently. tela-web passes `isSecure` from the request's protocol.

- **Cron and queue handlers run far from D1** (Paris and Los Angeles in the spikes, 160–250 ms per round trip), and placement never moves them. Only a fetch handler pinned with `placement.region = aws:ap-southeast-1` sits beside the Singapore primary (6–10 ms). That is why every job body runs behind `SELF.fetch()`.

A Worker branch that answered a missing `/assets/*` 404 was written for this and could never run; short of listing `/assets/*`, which runs the Worker for every asset, the edge cannot say 404. The old `sw.js` cached any 200 under the asset's name, and swapped `/` to the new shell without fetching what it loads, dropping the old shell's files while a tab could still be booting it. So the visit after a deploy could lose that race and boot blank, a shell just swapped to was blank offline, and after a second deploy the cached shell asked for scripts the network no longer had and kept the app under their names (Chromium: "Expected a JavaScript-or-Wasm module script but the server responded with a MIME type of "text/html""). The worker now keeps a hashed file only if its type matches its extension, swaps the shell only once everything it loads is cached, and keeps the previous shell's files; `SHELL` went to v2 to drop what v1 kept. Test a cache against a network that answers wrongly with a 200 (`apps/reader/test/sw.test.ts`), not only one that fails.
- **`/` is two pages, so the app shell does not come from it.** The edge renders `/` for a visitor, with the edition handed over in `#tela-data`, and answers a member (by the session cookie) with the plain shell (ADR 0035). `sw.js` took its shell from `/` and answers every navigation with it, so a visitor's worker would have kept the landing and painted it, its handover days old, on every page until the app replaced it; Playwright blocks service workers, so no e2e could have seen it, and review found it. Two review rounds found it in pieces. A test that checks for a leak through a snapshot sees only the feeds that account follows; look at the server's rows.

The password a joiner chose was saved after that, and a refusal told in the sheet: `/` and `/join` send a member to `/reading`, and that redirect closed the sheet, warning and all, and beat the sheet's own Discover whenever the save was slow. - **The shell worker answers every navigation, so a link to a file must not look like a page.** A click on `/l/<id>.rss` booted the app at an address it has no page for. `sw.js` lets a navigation to any path with a file extension go to the network (ADR 0062); never give an app route a dot.
- **A rendered page's canonical is its cache key's address.** `?hl=` pins a page only when it names the language rendered, and the colo keeps a pinned copy apart (`.hl` in the key), or a crawler's French copy would answer an English visitor. A new public page needs `pageAddress` and `headOf` in `ssr.tsx`, an `indexable` rule if a member can publish it, a sitemap entry, and its path in `run_worker_first` by name (ADR 0060).
- **OpenCC converts words, and a Taiwan word can mean something else.** It turned 账户已注销 ("account closed") into 登出 ("signed out"). Read the generated zh-Hant for any string about accounts, payment or law, and put the fix in `messages/zh-Hant.overrides.json` (舉報 → 檢舉 is there for reports), or word the Simplified differently.

## How to

- **Add a table**: edit `packages/data/src/schema/`, `bun run db:generate`, review the SQL, and test what depends on the engine in `packages/data/src/contract.ts` (run on libSQL and D1). A synced table also needs `seq`, its pull query in `packages/data/src/queries/sync.ts`, its row type and reducer in `packages/sync`, and its name in the device's table list.
- **Add background work**: a kind in `apps/jobs/src/kinds.ts` (a due query over a domain row, lease TTL, backoff, queue, handler, what exhaustion writes); the logic in `packages/ingest/src/pipeline` or `apps/jobs/src`, tested with the portable runner and the fixture HTTP server. Name the kind in `docs/OPERATIONS.md`.
- **Add a mutation**: its schema in `packages/sync/src/mutations.ts`, its statements in `apps/api/src/sync/push.ts` (guarded by the mutation id, resolved by `at`), its prediction in `packages/sync/src/client.ts`, and a case in the convergence test.
- **Add a UI string**: `apps/reader/messages/en.json`, `zh-Hans.json` and `fr.json`, same key and arguments in each, then `bun run i18n:hant` to regenerate `zh-Hant.json` (`apps/reader/test/messages.test.ts` and `hant.test.ts` check).
- **Add a line to a mail**: `apps/api/src/mail-text/en.json`, `zh-Hans.json` and `fr.json`, same key and `{placeholders}` in each, then `bun run i18n:hant` to regenerate `zh-Hant.json`. An English mail must stay as it was unless the change is to English: `apps/api/test/mail.test.ts` pins it, and checks the catalogues against each other.
- **Add a reading language**: `READING_LANGUAGES` and every reader's `LANGUAGE_NAMES` in `packages/shared`, its name in the prompt's map (`packages/llm/src/prompt.ts`), its `PILL_LABELS` and `CIRCLE_LABELS` entries (`apps/reader/src/lib/format.ts`: a word, and the one or two characters the header's language circle shows), and the copy that lists the languages (`front.intro`, the About page). It is also a UI locale (the types require it), so it needs a catalog and an info module. Its archive's titles become due at once (`docs/OPERATIONS.md`).
- **Add a runtime setting**: a key in `SETTINGS` (`packages/shared/src/settings.ts`) with its kind and default (`null` is no limit, `0` is nothing at all), read inline by the statement that enforces it (`settingSql`), or with `readSettings` where JavaScript decides; the console's Settings area and `bun run admin set` reach it with no more code (ADR 0056).
- **Add or change an API route** (ADR 0065): the rule as a shared function in `apps/api/src/core/` (an `Actor` in, a neutral result out), or the existing one the web's route already calls; its v1 request and answer as zod schemas in `packages/ext/src/schema.ts` (camelCase, epoch milliseconds, each enum said open or closed), a pure mapper from the function's result, and the route in `apps/api/src/gateway/v1/` behind `requireScope` with `exempt: false`; a golden fixture under `docs/api/` and the OpenAPI document regenerated (their tests fail until both match); the route in `docs/api/v1.md` and a line in `docs/api/CHANGELOG.md`, and a feature name in `/meta` for an addition. Within v1, only add. A public answer the same for every viewer can be kept at the gateway's colo (`PUBLIC_PATH` in `apps/gateway/src/gateway.ts`); a route that takes no token goes in `takesNoToken` there.
- **Add a translation provider**: implement `Translator` (`packages/llm/src/types.ts`) or add a case to `createTranslator` (`packages/llm/src/providers.ts`), extend `configFromEnv`, and document the env vars in `docs/OPERATIONS.md`. Output validation stays in `translateBlocks`.
