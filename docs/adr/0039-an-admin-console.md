# 0039 — An admin console: act where the digest only reports

Status: accepted (2026-10-05). Complements 0027 (the digest stays the alarm). Makes an exception
to 0025 for one operator-only chunk. Gives 0011's "support action" (removing a claim) and 0018's
veto (`rejected`) a place to be done, and adds an operator's vouch for a claim.

## Context

The operator ran Tela through `bun run admin` (invites, codes, curated blogs) and, for everything
else, hand-written SQL through `wrangler d1 execute`: featuring or hiding a blog, reviving a feed,
retrying a dead letter, removing a claim. 0011 said featuring was "SQL for now, an admin page
later", and 0027 chose a Monday digest over a dashboard, because a dashboard is something to
remember to look at. The digest says what is wrong; it gives no way to act on it, and every act
was a statement typed against production.

The owner's Claude Design project draws a console ("Tela Admin", direction 2a, "Ledger,
refined"): a table per area with filter pills and a search, the likeliest action on every row, a
record panel beside the table, a bulk bar, an undo toast, and the keyboard for all of it. It was
drawn for about 500 members and assumes features Tela does not have: reports and a moderation
queue, Editor and Moderator roles, suspensions, invitations by email with open tracking, a dollar
budget, and a cache-hit rate.

## Decision

**A console for what Tela has, and nothing it would have to pretend.** Overview, Claims, Sites,
Feeds, Discover, People (read-only, plus signing a member out everywhere), Invitations,
Translation (in tokens) and System. Reports, roles, suspensions, dollar costs and cache hits are
neither built nor shown: each is a feature of its own, and none has a row behind it today.

**One flag, granted from the command line.** `profiles.is_admin`, in the schema since the first
migration and read by nothing until now, says who may open the console. Only the operator's token
sets it (`bun run admin grant|ungrant <email>`), so an admin's stolen session cannot make another
admin. The flag syncs with the profile so the account menu can offer the console; tela-api reads
it from D1 on every admin call, past the signed five-minute session copy, so an ungrant or a
sign-out closes the console at once.

**Under `/api/v1/admin`, never `/api/admin`.** The console acts with the member's cookie, so it
takes every check a member call takes: the session, the client's protocol, the member it names,
and tela-web's same-origin rule for writes. `/api/admin/*` is let through from any origin because
it takes the operator's bearer token instead; a cookie-authenticated route there would be a
cross-site write.

**Reads over the network, in a chunk of its own.** 0025 has every screen render from the device's
rows. The console shows what no device holds (every member's account, every feed's errors), so
it reads from tela-api, and it is loaded with `import()` only when an admin opens `/admin`: the
reader's shell carries none of it. It writes nothing to the device's store.

**Every write is audited in its own batch, and undone only if nothing moved since.** One target
is one batch: an `insert … select` into `admin_actions` reads the value it replaces in the same
snapshot, then the change runs under the same condition. A bulk request shares a group id, which
is the undo token. An undo restores each `from` only where the target still holds the action's
`to`; one guard per target aborts the whole batch otherwise (409 `changed_since`), as a lost
lease's fence does. One-shot actions (fetch now, re-check, retry) have no undo.

**An operator's change beats the work in flight.** Pausing a feed, setting its region, rejecting
or removing a claim delete the item's lease in the same batch. A job already running then finds
its fence refused at commit, and writes nothing over the operator's choice.

**What sticks, and what does not.** `private` is not an operator's to choose: an unclaimed site
with three readers is listed again on the next subscribe. So the console offers Feature, List,
Hide (`rejected`, the veto 0018 named) and Restore, which returns a site to what the doors say.
A merged feed cannot be unmerged: its next fetch would merge it again.

**A vouch, not a verification.** "Verify by hand" sets `site_claims.vouched_by` and runs the
check. The check skips only the proof: it still reads the home page for the feeds the site
declares, because which feeds a claimed site carries depends on them (0011). A member's own
re-check clears the vouch.

**English and Simplified Chinese.** The console's words live in its own catalogues inside its
chunk: English and Simplified written by hand, Traditional generated by OpenCC like every other
Traditional string. A French interface reads the console in English.

## Consequences

- Migration 0006: `admin_actions`; `dead_letters.resolved_at`, `resolution`, `resolved_by`;
  `site_claims.vouched_by`, `reviewed_at`; `llm_calls.feed_id`, backfilled where a call names its
  post. The health check counts only unresolved dead letters.
- The digest still arrives every Monday, and the dead-man's switch still pings. The console is
  where the operator acts on them, not a replacement for either.
- After a deploy, a cached shell may ask for an admin chunk the network no longer has; the console
  reloads once rather than failing on the single-page fallback's `index.html`.
- An audit row never holds an email address: an invitation to an address is named by the member
  it made, and a cancelled hold by its redemption id. Searches for an address run in the browser,
  so no address reaches a request's URL, and the Workers' logs, either.
- The console's "Invite by email" counts each mail against the address's limit for sign-in codes:
  better-auth counts nothing for a call tela-api makes itself.
- A second operator is a grant away, with the same powers as the first. Roles wait until there is
  a reason to give someone less.
