# API v1

Everything here is under `https://api.telaread.com`, and every route but `/meta`,
`/v1/openapi.json` and OAuth's own endpoints takes an access token (see
[authorization.md](authorization.md)). The formats below are summaries:
[openapi.json](openapi.json) has every field, and [v1/examples/](v1/examples/) an answer for every
route. v1 is in preview ([policy.md](policy.md)).

## Conventions

- **JSON in and out**, UTF-8. Keys are camelCase. Times are epoch milliseconds. Ids Tela makes are
  integers that grow in order (posts, feeds, blogs); ids your app makes are strings of 8 to 40
  characters (mutation ids, highlights, folders); a member's id is a string.
- **Unknown fields are ignored.** Tela adds fields within v1; your app must read past them. An
  enum documented as *open* may gain values within v1: treat an unknown value as the docs say for
  that field. A *closed* enum changes only in a new version. In [openapi.json](openapi.json), an
  open enum is marked `x-extensible-enum`.
- **Errors** are `{ "error": "<code>", … }` with an HTTP status (see *Errors*). Every 401 and 403
  carries `WWW-Authenticate` (RFC 6750), `app_suspended` included; 429 and 503 carry
  `Retry-After`, in seconds. The OpenAPI document lists 401, 403, 429 and 503 on every route that
  takes a token.
- **Only the documented paths answer:** `/meta`, `/v1/…`, `/o/…`, `/img/…`, `/oauth/…`,
  `/.well-known/oauth-authorization-server` and `/robots.txt`. Anything else is 404 `not_found`.
- **Every answer** carries `Tela-API-Version`, the version that answered it (`1` for everything
  under `/v1/`), `X-Robots-Tag: noindex` and HSTS. Once a version is deprecated, its answers also
  carry `Deprecation` and `Sunset` headers ([policy.md](policy.md)); none is deprecated yet.
  Answers set no cookies, and cookies sent are dropped.
- **No CORS.** The API is for native apps and tools; a web page cannot call it.
- **Authorization:** `Authorization: Bearer tela_at_…` on every call that takes a token. A route
  that changes anything needs `write`; a `read` token gets 403 `insufficient_scope`.

## `GET /meta`

No token. What the API offers now, so an app can check before it relies on something:

- `current` and `oldest`: the newest version and the oldest still answering;
- `versions`: each with its `status` (open enum: `preview`, `stable`, `deprecated`) and `sunsetAt`
  (when it stops answering, or null);
- `features`: per version, the names of what it offers. Check for a feature by name rather than
  assuming it from a version: additions within v1 are announced here;
- `limits`: the most mutations and bytes in one push (`pushMutations`, `pushBytes`), rows in one
  sync page (`pageRows`), keys in one bodies request (`bodiesPerRequest`), the sync horizon in days
  (`horizonDays`), the reading languages, and the site's current daily limits:
  `translationsPerDay`, `feedsPerDay`, `maxSubscriptions` and `unsubscribedPostsPerDay` (null is
  no limit, 0 is none). The operator can change these while Tela runs;
- `oauth.metadata`: the authorization server's metadata URL.

The answer may be cached for five minutes (`Cache-Control: public, max-age=300`), so a limit the
operator changes can take that long to show here.

## The member: `GET /v1/me`, `GET /v1/usage`

`/v1/me` (read): the member's `handle`, `displayName`, `avatar` (an absolute URL, or null),
`readingLanguage` (null follows their interface language), the `scope` this token has now, and
`email` only when the member let your app see it.

`/v1/usage` (read): where the member stands today, one count for the web and every app:

- `translations`: `perDay`, `usedToday`, `waiting` (put off to tomorrow), `resetsAt`;
- `feeds`: `perDay` (feeds new to Tela), `addedToday`, `pending` (an import's overflow, added on
  the days after);
- `subscriptions`: `max` and `count`;
- `posts`: `perDay` (full posts from blogs they don't subscribe to), `openedToday`, `resetsAt`;
- `rateLimits`: your app's requests a minute per member and in all.

Days are UTC days; `resetsAt` is the next UTC midnight. `null` is no limit.

## Sync

The member's data comes as rows your app keeps on the device, as Tela's web app does. Every screen
should render from what the device holds; sync keeps it current behind the screen.

`GET /v1/sync?lang=<language>[&cursor=<cursor>][&types=<type>,<type>]` (read)

- `lang` is required: the reading language titles and body translations come in, one of the
  reading languages in `/meta` (`zh-Hans`, `zh-Hant`, `en`, `fr`).
- `cursor` is what the last pull answered; leave it out (or send `0`) for a snapshot.
- `types` limits the pull to some row types. Left out, it is v1's default set: the fourteen types
  below, which never changes within v1. A row type added later comes only to an app that names it
  in `types`.

The answer:

```json
{
  "cursor": "eyJ2IjoxLCJzIjo…",
  "more": false,
  "reset": true,
  "lang": "en",
  "types": ["profile", "prefs", "subscriptions", "feeds", "sites", "articles", "titles", "states",
            "recommendations", "highlights", "translations", "folders", "feedFolders", "follows"],
  "rows": { "profile": { … }, "prefs": [ … ], "subscriptions": [ … ], … },
  "removed": { "articles": [] }
}
```

- **`reset: true`** is a snapshot: drop every row you hold for this account and take these.
- **`removed.articles`**: ids of posts to drop from the device. It is empty today; handle it
  anyway, since Tela may start filling it within v1.
- **`more: true`**: the page ended early. Pull again at once with the new `cursor`, and keep
  adding rows, until `more` is false.
- **The cursor is opaque.** Store it with the rows, in the same write, and send it back as it
  came. It records the point you hold every row up to, the language, and the row types; asking in
  another `lang`, or for a type the cursor does not cover, starts over with a snapshot (`reset`).
  So does a cursor Tela did not make, and a cursor ahead of Tela's own data (after a restore).
- **Rows replace** what you hold under the same key (an article by `id`, a state by `articleId`, a
  title by `articleId` and `lang`, and so on). `profile` is one object, or null when it did not
  change.
- **When to pull:** when the app starts or comes to the foreground, after every push, and every
  minute or so while it is open. A snapshot holds the last `limits.horizonDays` days (30) of the
  posts of the feeds the member follows, and every post they keep.

### Row types

| Type | Key | What it is |
|---|---|---|
| `profile` | — | The member's handle, name, bio, avatar, reading language, and whether they show their subscriptions and likes |
| `prefs` | `key` | Preferences, from v1's allowlist only, each with a fixed value type; a key you do not know, ignore |
| `subscriptions` | `feedId` | A feed the member follows, its `watermarkId`, and `deletedAt` once they unsubscribe |
| `feeds` | `id` | A feed: its blog (`siteId`), address, title, `status` (open enum: `active`, `failing`, `dead`, `paused`, …) and when it last fetched and last listed a post |
| `sites` | `id` | A blog: home, title, description, favicon, language, reader count, whether it is claimed, and `translationAllowed` |
| `articles` | `id` | A post: its feed, URL, title, author, dates (`sortAt` is the order lists use; `fetchedAt` is when Tela first fetched it, which the horizon counts from), source language, excerpt, `contentKey` (null when Tela holds no body), length, likes and recommendations |
| `titles` | `articleId`, `lang` | A post's title and excerpt translated into the cursor's language. Only translations that exist are sent |
| `states` | `articleId` | When the member read (`readAt`) and liked (`likedAt`) a post, and `markedUnread`: true when they marked it unread by hand and have not read it since |
| `recommendations` | `articleId` | The member's public recommendation, with its note; `deletedAt` once taken back |
| `highlights` | `id` | A private highlight with its note; `deletedAt` once deleted |
| `translations` | `contentKey`, `lang` | A body translation in the cursor's language: its state, finished chunks, the finished object |
| `folders` | `id` | The member's private folders; `deletedAt` once deleted |
| `feedFolders` | `feedId` | Which folder a blog is in (`folderId` null: none) |
| `follows` | `userId` | A member this member follows: handle, name, avatar; `deletedAt` once unfollowed |

**`feeds` and `sites` are not the member's subscriptions.** They also carry blogs the member does
not follow: the feeds of posts they keep, and the blogs in their own blogrolls. Build the list of
what they subscribe to from `subscriptions` (the rows without `deletedAt`), and look each one's
feed and blog up in `feeds` and `sites`.

### Read and unread

Whether a post is read is decided by the first of these that holds:

1. its state has `readAt`: read;
2. its state has `markedUnread`: unread, whatever the watermark or its age, until a later read;
3. its id is at or below its feed's subscription `watermarkId`: read;
4. it was fetched (`fetchedAt`) more than `limits.horizonDays` days (30) ago: read;
5. otherwise unread, as is a post with no state at all.

A post marked unread by hand is sent even when it is older than the horizon. `markAllRead` moves
the watermark; `markRead` and `markUnread` write a state.

### What counts as deleted

Tela deletes softly. Nothing in a pull tells you to remove a row except:

- a highlight, folder or follow with `deletedAt`: remove it;
- a subscription with `deletedAt`: the member left that feed. Remove its posts, except those they
  **keep**: liked (`likedAt`), recommended (a recommendation without `deletedAt`), or highlighted
  (a live highlight). Keep the subscription row, or drop it; a later subscribe sends a new one;
- a site whose `translationAllowed` turns false: remove its titles and body translations (below);
- a post listed in `removed.articles`: remove it.

Posts older than the horizon are not sent again in a snapshot unless the member keeps them. You may
keep older posts you already hold, or let them go.

### Writers' choices

A writer can turn translation off for their blog. Tela enforces it on the server, and your app must
too:

- sync sends no titles and no body translations of a blog whose `translationAllowed` is false;
  asking for one (`POST /v1/translations`) answers `{ "status": "unavailable" }`, and its status
  (`GET /v1/translations/{contentKey}/{lang}`) answers 200 `{ "translation": null }`;
- when a blog's `translationAllowed` turns false in a pull, delete the titles and translations you
  hold for its posts, and show its posts as written;
- when it turns true again, Tela sends that blog's titles and translations again in the next
  pulls.

Show the original post's link wherever you show its text, and its blog's name.

## Mutations

Everything your app changes goes through one route, as a queue it can send while offline and
again after a failure.

`POST /v1/mutations` (write), with `{ "mutations": [ … ] }`: at most `limits.pushMutations` (50)
mutations and `limits.pushBytes` (1 MB) in one push.

Every mutation has:

- `type`: what it does (closed enum, below);
- `mid`: an id your app mints, unique per mutation (8 to 40 characters; a UUID will do). Sending
  the same `mid` again changes nothing, so a push that failed or timed out is safe to send again
  as it was;
- `at`: when the member did it, by the device's clock. A time ahead of Tela's counts as Tela's now.
  Between two changes to the same thing, from any device or the web, **the later `at` wins**.

| `type` | Fields | |
|---|---|---|
| `markRead`, `markUnread` | `articleId` | |
| `setLiked` | `articleId`, `liked` | |
| `markAllRead` | `upTo`, optional `feedId` | Every post up to `upTo` (the highest id the app showed), in one feed or all |
| `subscribe`, `unsubscribe` | `feedId` | |
| `setPref` | `key`, `value` | A key from v1's allowlist, with that key's value type |
| `setReadingLanguage` | `language` | A reading language, or null to follow the interface language |
| `recommend` | `articleId`, `note` | `note` up to 500 characters, or null |
| `unrecommend` | `articleId` | |
| `putHighlight` | `id`, `articleId`, `contentKey`, `side`, `lang`, `leafId`, `start`, `end`, `quote`, `prefix`, `suffix`, `note` | Makes or edits a highlight (see *Highlights*) |
| `deleteHighlight` | `id` | |
| `follow`, `unfollow` | `userId` | A member's account id: a reader card's `userId` on the public side, or a `follows` row's |
| `putFolder` | `id`, `name` | Makes or renames a folder |
| `deleteFolder` | `id` | Its blogs are left in no folder |
| `fileFeed` | `feedId`, `folderId` | `folderId` null takes the blog out of its folder |

A deletion wins over any later edit of the same highlight or folder.

The answer has one result per mutation sent, in order:

```json
{ "results": [
  { "mid": "9b1f…", "status": "applied" },
  { "mid": "77c2…", "status": "rejected", "error": "subscription_limit" }
] }
```

- `mid` is the one you sent, or null when the mutation carried none Tela could read (it is then
  `rejected`). Match results to your mutations by position.
- `applied`: it holds, and a pull begun after this answer reflects it. A replay is `applied` too.
- `rejected`: it never will; drop it and undo what your app showed. `error` is an open enum:
  `invalid` (the mutation is malformed, or a pref key is outside the allowlist),
  `subscription_limit` (a subscribe past the member's cap: tell the member). Treat an unknown code
  as `invalid`.

### Offline obligations

1. Keep unsent mutations on the device, in order, with their `mid` and `at`, and show their
   effect at once over the rows you hold.
2. Send them in order, at most 50 at a time. On a network failure or a 5xx, send the same
   mutations again later, unchanged.
3. When a push answers, drop every mutation it answered, applied or rejected, and pull.
4. After every pull, show the pulled rows with the mutations still unsent laid over them again.
5. Never edit a mutation already sent. A later change is a new mutation with a later `at`.

Your `mid`s are your app's own: they never collide with another app's or the web's, so one app
cannot replay or cancel another's.

### Highlights

A highlight lives in one **leaf** of a post: an element of the body's HTML with a `data-tb`
attribute (a paragraph, list item, cell or heading). `leafId` is that attribute's value; `side` is
`original` or `translation` (the same leaf in the translated body), and `lang` that side's
language.

`start` and `end` count UTF-16 code units into the leaf's text content (what JavaScript's
`textContent` and `String.length` count): not bytes, not code points. `quote` is the text between
them (at most 2,000 characters), and `prefix` and `suffix` up to 32 characters either side, so the
passage can be found again when the post changes and its offsets no longer fit. `note` is at most
2,000 characters, or null. `contentKey` is the body the highlight was made on.

`end` must be greater than `start`, and `quote.length` (in UTF-16 code units) must equal
`end - start`. A highlight that breaks either is `rejected` with `invalid`.

A highlight that overlaps or touches another in the same leaf should be merged into one before you
send it, as Tela's web app does.

## Bodies and images

A post's full text is an immutable **content object**, addressed by the article's `contentKey`.

`GET /v1/bodies?keys=<key>,<key>,…` (read): up to `limits.bodiesPerRequest` (25) content keys.

```json
{
  "objects": { "<key>": { "format": 1, "key": "<key>", "lang": "en", "blocks": [ … ], … } },
  "refused": { "<key>": { "error": "post_limit", "limit": 100, "resetsAt": 1761609600000 } }
}
```

A key whose object does not exist is in neither. A content object never changes, so keep it as
long as you like; a new version of a post has a new `contentKey`.

The object, `format: 1`:

- `blocks`: the body as top-level blocks, each with its `tag`, its sanitized `html`, and the ids of
  the `leaves` it holds;
- `leaves`: each leaf's hash and length;
- `images`: the original image URLs;
- `stats`: characters, words, minutes to read;
- `lang`, and `norm` (the version of the rules it was made under).

The block HTML is sanitized and safe to render. Its images point at Tela's proxy, as paths:
`/img/<contentKey>/<index>`. Fetch them from `https://api.telaread.com` with the access token, so
a web view inside your app has to load them through your code, not by itself. The proxy serves
raster images only (no SVG), at most 10 MB, and keeps a failure for ten minutes.

The objects also have addresses of their own, for one at a time (read):

- `/o/c/<contentKey>.json`: a content object;
- `/o/t/…`: a finished translation, at the path a translation row's `object` names;
- `/o/tc/…`: a chunk of a translation still running, at the paths in its `chunks`.

### The daily limit on posts from other blogs

A member may open as many posts as they like from blogs they subscribe to. From any other blog,
they may open `limits.unsubscribedPostsPerDay` posts a UTC day (100 now), on the web and in every
app together.

- A post counts once a day, however often it is fetched; its translations and images are free once
  its body was allowed.
- Posts the member keeps from blogs they left count too.
- A body refused for the limit is listed under `refused` in `/v1/bodies`, and answered 429 with
  `{ "error": "post_limit", "limit", "resetsAt" }` and `Retry-After` at `/o/…` and `/img/…`.
- **Prefetch only posts of subscribed blogs**, which are never counted. Fetch a post from any other
  blog only when the member opens it.
- When a post is refused, show its excerpt, say when more open (`resetsAt`, in the member's own
  time), and offer to subscribe to the blog and to read it on the blog. Do not ask for it again
  before `resetsAt`, unless the member subscribes.
- `/v1/usage` says how many are left.

Your app is never exempt, even for an admin's account.

## Translations

Titles are translated for everyone ahead of time and come through sync. A post's body is
translated when a member asks, and streams in, a few paragraphs first.

`POST /v1/translations` (write), with `{ "articleId": 123, "lang": "zh-Hans" }`:

```json
{ "status": "running", "translation": { "contentKey": "…", "lang": "zh-Hans", "state": "running",
  "chunks": ["/o/tc/…"], "object": null, "dueAt": null } }
```

`status` (open enum):

- `ready`: done; fetch `translation.object`.
- `running`: on its way; fetch the chunks as they appear, and poll the status.
- `waiting`: the member's day or the site's is full; Tela will translate it at `translation.dueAt`
  (the next UTC midnight). Don't poll before then.
- `refused`: no room today or tomorrow: `reason` is `member` (their daily translations) or `site`
  (Tela's daily budget), until `resetsAt`.
- `unavailable`: the writer turned translation off, or Tela holds no body for this post.

Treat an unknown status as `unavailable`. Asking needs `write`, because a new translation counts
toward the member's daily translations. One that already exists, or a conversion between
Simplified and Traditional Chinese, counts nothing.

`GET /v1/translations/{contentKey}/{lang}` (read): `{ "translation": { … } }`, or `null` for none.
Poll it while a translation runs, every few seconds at most. For a blog whose writer turned
translation off it answers 200 with `{ "translation": null }`, whatever exists. Translation rows
also come through sync, in the cursor's language.

A translation row's `state` (open enum): `requested` and `running` (on its way), `waiting` (due at
`dueAt`), `done`, `partial` (some blocks stayed in the source language), `failed`, `skipped`.

The finished object (`/o/t/…`, `format: 1`) has one HTML string per block of the content object,
in the same order, so the two line up block by block; a block with no translation carries its
source. A chunk (`/o/tc/…`) maps block indexes to HTML, and the chunks are numbered in order.

## Adding feeds

All three need `write`, and are held to the member's limits: feeds new to Tela per day, the
subscription cap, and how often per hour.

- `POST /v1/feeds/discover` with `{ "url": "https://example.com" }`: the feeds at an address,
  each `{ feedUrl, title, feedId }`. `feedId` is set when Tela already has the feed, so subscribing
  to it is free.
- `POST /v1/feeds` with `{ "url": … }`: adds the feed and subscribes the member. The answer has the
  `feed` and `site` rows and `added` (true when the feed is new to Tela and counted toward today).
  429 `feed_limit` (`limit`, `resetsAt`) when today's new feeds are spent; 409
  `subscription_limit` at the cap. A feed new to Tela has no posts until its first fetch, within a
  minute or so; pull again.
- `POST /v1/feeds/opml` with the OPML document as the body: subscribes to the feeds Tela has,
  adds new ones up to today's count, and puts the rest off to the following days. The answer says
  how many were `subscribed`, `added`, `waiting` and `over` the cap, with the limits and
  `resetsAt`. At most 1 MB.

Discovery is limited to 30 an hour, adding to 120 an hour, and imports to 5 an hour, per member.

## The public side

What anyone signed in to Tela can browse, the same for every member (read). Lists carry `page`
(from 1) and `more`; ask for `page=2` and so on while `more` is true.

| Route | What |
|---|---|
| `GET /v1/discover/week?lang=` | This week's most recommended posts |
| `GET /v1/discover/articles?topic=&lang=&page=` | Every public post, newest first |
| `GET /v1/discover/blogs?topic=&lang=&page=` | Listed blogs |
| `GET /v1/discover/blogrolls?lang=&page=` | Public blogrolls |
| `GET /v1/discover/readers?lang=` | Readers who recommend or show what they read |
| `GET /v1/sites/{id}?lang=&page=` | A blog's card, its feeds and a page of its posts |
| `GET /v1/profiles/{handle}?lang=&page=` | A member's card and recommendations; their likes and subscriptions only when they show them |
| `GET /v1/blogrolls/{id}?lang=` | A public blogroll and its blogs, with the owner's notes |
| `GET /v1/search?q=&lang=&page=` | Posts and blogs |
| `GET /v1/articles/{id}` | One post, to open it |

The cards are small and the same everywhere: a **post** (`id`, `siteId`, `title`,
`translatedTitle`, `excerpt`, `url`, `author`, `publishedAt`, `likeCount`), a **blog** (`id`,
`title`, `homeUrl`, `description`, `faviconUrl`, `primaryLang`, `readerCount`, `topics`) and a
**reader** (`userId`, `handle`, `displayName`, `avatar`). A reader's `userId` is their account id,
what `follow` and `unfollow` name; it grants nothing on its own.

- `translatedTitle` is in `lang` when you pass it, else in the member's reading language, and is
  never given for a blog whose writer turned translation off. **Pass `lang`**: Discover, blog,
  profile and blogroll answers that name it are kept near the member for five minutes, come
  faster, and do not count toward your rate limits when served from that copy (*Rate limits*).
- A reader count is shown only from three readers up.
- **No public answer carries a content key.** To open a post from the public side, ask
  `/v1/articles/{id}`: it answers `{ article, feed, site }` in sync's row shapes, content key
  included, so you can hold the post as if it had synced. Then fetch its body from `/v1/bodies`,
  where the daily limit counts it if the member does not subscribe to its blog.
- `/v1/articles/{id}` answers only a post the member could have reached: one of a blog Tela lists
  publicly, of a feed they follow, one they keep, or one of a blog in a public blogroll. Any other
  id is 404 `not_found`.

## Errors

| Status | `error` | Meaning |
|---|---|---|
| 400 | `invalid_request` | The request is malformed. Fix it; sending it again will not help |
| 400 | `invalid_url` | Adding or discovering a feed: the address is not one Tela can fetch |
| 400 | `opml_invalid` | Importing: the body is not an OPML document Tela can read |
| 401 | `invalid_token` | No token, or one that is unknown, expired or ended, or the member's account can no longer be used. Refresh once; if that fails, connect again |
| 403 | `insufficient_scope` | The token is `read` and this needs `write` |
| 403 | `app_suspended` | The operator has cut your app off for now. Keep the tokens: they work again once it is restored |
| 404 | `not_found` | No such thing, not one this member may see, or a path the API does not serve |
| 405 | `invalid_request` | A method other than `GET` or `HEAD` at `/v1/bodies`, `/o/…` or `/img/…`. `Allow` says which |
| 409 | `subscription_limit` | The member is at their subscription cap |
| 413 | `too_large` | The body is past its limit |
| 422 | `unreachable` | Adding or discovering a feed: Tela could not reach the address |
| 422 | `not_a_feed` | Adding or discovering a feed: there is no feed at the address |
| 422 | `feed_too_large` | Adding or discovering a feed: the feed is past the 10 MB Tela reads |
| 429 | `rate_limited`, `feed_limit`, `post_limit` | Too many requests, or a daily limit. Wait `Retry-After` seconds, or until `resetsAt` |
| 500 | `internal` | Tela failed while answering. Try again later, with backoff |
| 503 | `apps_paused` | The operator has stopped every app for now. Wait `Retry-After` |
| 503 | `unavailable` | Tela could not answer. Wait `Retry-After` and try again |

`error` is an open enum: an unknown code is handled by its status. A 5xx with no body is a failure
to retry later, with backoff. `invalid_url` and the 422s are about the address the member gave:
tell them.

**Images fail in plain text.** When `/img/…` cannot serve an image, it answers `text/plain`, not
JSON: 404 (no such image), 403 (an address Tela will not fetch), 413 (past 10 MB), 415 (not a
raster image) or 502 (the blog's server failed). These are kept for ten minutes, so do not ask for
the same image again sooner. A refusal of the token or of the day's limit is JSON there too, as
everywhere.

## Rate limits

Every call with a token that reaches Tela counts toward two windows of one minute: your app's
requests for this member (120 a minute unless the operator set another limit for your app) and
your app's requests for everyone together (6,000 a minute unless set otherwise). `/v1/usage` says
the limits that hold. Past either, the call is answered 429 `rate_limited` with `Retry-After` until
the minute turns; it still counts.

Two kinds of answer come from the API's edge near your app without reaching Tela, and are not
counted:

- a public answer from the edge's copy (*The public side*: one that names `lang`, kept five
  minutes);
- a body, translation or image of a post the edge allowed for this token in the last 60 seconds.

Because those copies are served without asking Tela, they can still answer for up to a minute
after the operator cuts your app off or stops every app, or after the connection ends.
